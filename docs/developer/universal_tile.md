# The universal tile template

`src/templates/hw/tiles/universal_tile.sv.mako` is the one template that turns any *isle* — a topology-agnostic component with its own AXI ports — into a *tile* of the 2D mesh: a wrapper that holds the FlooNoC router at the mesh crossing, the chimney that converts the isle's AXI traffic into flits and back, and everything that has to sit between the two. Every `<type>_tile.sv` under `generated/hw/` comes out of it, one per component type, and so does the tile of the host and of every memory isle. The dummy tile that fills an empty coordinate is a separate, much smaller template (`dummy_tile.sv.mako`) that keeps only the router.

## Two halves: decide, then emit

The template is a Python header followed by the SystemVerilog it renders, and the split is deliberate: **every decision is taken once, in the header, and the RTL below only reads the results**. The header parses the isle's own header file with pyslang (`get_isle_info`), which yields its ports, its parameters and the contract literals the component declares (`OffloadContract`, the collective slot offsets, the DMA hart, the wide user layout — see the component standardization document, section 8), and reads the SoC description for the topology, the networks, the collective channels and the placement. From those it derives a small set of booleans and lists that the rest of the file switches on. The ones worth knowing when reading a generated tile:

*   **`has_master` / `has_slave`, per network (`has_master_narrow`, `has_master_wide`, …):** which AXI ports the isle exposes and on which network each rides. They decide which chimney sides are connected, which isolation cells exist and whether error slaves terminate the unused ports.
*   **`noc_mode` (`joined` or `dual`) and `use_join`:** a `joined` isle with a single slave port receives narrow and wide traffic through a `floo_nw_join`; a `dual` isle has one port per network and needs none.
*   **`use_mcast`:** the component is a multicast target (`features.multicast_target`). Its chimney is then instantiated with the collective route configuration and the collective SAM rules; every other chimney is `NoMcast` and structurally cannot inject or receive a collective.
*   **`narrow_red_on` / `wide_red_on`:** the reduction channels the SoC declares. The first adds the per-tile integer ALU (`floo_alu_top`) behind the router's narrow offload port; the second adds the wide offload plumbing — the `red_wide_*` types FlooGen emits only with the channel, the router's wide offload ports, and the isle's offload interface, tied off when the channel is absent.
*   **`stamper_on` and `stamper_windows`:** the isle declares collective contract slots (a barrier slot and the alias base at least) and the group has more than one instance; the wide offload port plays no part in this decision, so an isle without an FPU-backed offload gets its stamper for the narrow collectives all the same. The stamper takes the instance base at run time from the isle's `instance_base_addr_i` port (component standardization 2.6), and an isle with slots but without that port is refused at generation. The geometry itself is computed by `src/core/collective_geometry.py`, the same code the placement report reads. The header then computes the address windows (base, span, group base, member mask, collective mask, slot offset, kind: column reduction, row reduction, barrier, multicast) the stamper will match — one per collective the group carries, the reduction ones decomposed by dimension — and validates them: power-of-two aligned boxes, column-fastest enumeration, uniform box height, slots aligned to the beat of their channel. `coll_csr` follows: when the windows include a reduction, the tile takes the reduction opcodes as ports (`coll_op_col_i`, `coll_op_row_i`), fed by the System Controller's `collective_ctrl` register.
*   **`wide_coll_user` and `slv_wide_adapt`:** the isle declares that its wide AXI user carries FlooNoC's `{collective_mask, collective_op}` (`OffloadWideUserLayout = "floo_collective"`). The wide isolation cell and the chimney's wide side are then typed with the collective types, and an inbound adapter rebuilds the network's plain wide request into the isle's own type with the user tied to Unicast.
*   **`mst_adapt` and the macro-boundary flags:** which master ports keep the isle's own AXI types and need an adaptation towards the network types (an ID zero-extended on the way in, truncated back on the response), and whether this tile sits on the boundary of a project exported as a macro, where the input-typed signals are widened back next to the chimney.
*   **`iso_nets`, `isle_owns_isolate`, `has_clk_ctrl`, `has_sysctrl_ports`:** who owns the AXI isolation (the isle, if it declares a cell of its own, otherwise this tile), whether the tile carries clock gating and reset control for a gated domain, and whether it is the host tile, which also flattens the register bus and hosts the system controller.

## What is emitted, in order

The rendered file follows a fixed order, and the banners in the template name the sections; a generated tile reads the same way, top to bottom:

1.  **Router ports and component I/Os.** The four cardinal directions always exist (`floo_req`, `floo_rsp`, `floo_wide` in both directions); the component-specific I/Os and interrupts are extracted from the isle header and exported on the tile with their original names, so the top sees the isle's interface through the tile unchanged.
2.  **Clock gating, reset control, AXI isolation ports.** Present for gated domains and for tiles that own their isolation cell.
3.  **The FlooNoC router** (`1 · floo_nw_router`), with the tile's collective configuration: the full emitted set where the isle hosts the wide offload consumer, the FP operations masked off everywhere else — reduction *computes* at every merging router, and only the compute tiles have an FPU behind the interface. The narrow integer ALU (`1b`) sits beside it when the narrow channel is declared.
4.  **The chimney** (`2 · floo_nw_chimney`) and its AXI wiring: the isle's traffic in the network's types, on the narrow and wide sides the isle actually has.
5.  **The collective stamper** (`2a`), narrow only, between the isle's master port and the chimney: it matches the generated windows on the AW address, rewrites the destination to the real slot and puts the member mask and the window's opcode in the AXI user — a constant for the barrier and the multicast, the System Controller's `collective_ctrl` field for the column and row reduction windows, which reach the tile through `coll_op_col_i` / `coll_op_row_i` — rebuilding every channel field by field. Everything outside the windows passes through untouched and the SoC-wide user width never changes.
6.  **Isolation cells and type adaptation** on the master side, the **join**, the **inbound wide adapter** and the **macro boundary** on the slave side, the **error slaves** on the ports the isle does not use. The two sides are not symmetric, on purpose. The slave side has no counterpart of the master adaptation block: where the isle takes its AXI types as parameters the tile injects the network's output types (or the join's), and where it keeps its own (the cluster subtile) the network signal is connected directly. A direct connection is correct only while the two structs have identical widths, so every such connection is guarded at elaboration: a `$bits` comparison of the whole request and response structs - which covers the `user` and `id` fields, the ones whose widths differ between an isle's own types and the network's - stops elaboration with both widths in the message, exactly as the master side does where two user layouts must coincide. The inbound wide adapter is the one place on this side where the widths legitimately differ and a converter exists instead of a guard. The join and the macro boundary are slave-only for a reason: a single master port attaches to one network and needs no split, and a macro's master port already carries the network's input type.
7.  **The isle instantiation** (`3 · i_isle`), with its parameters filled from the parsed header — instance identity as a port, package types resolved at the instantiation rather than passed as tile parameters (a `parameter type` on the wrapper would keep it from being a Verilator hierarchical block), the offload interface types when the wide channel exists.

## The two data paths

**Isle to network.** A store or a DMA transfer leaves the isle's master port, crosses the stamper if the tile has one (narrow only), then the outbound isolation cell, then enters the chimney, which converts it into flits and hands them to the router's local port. On the wide channel there is no stamper: a cluster that speaks collectives sets `{collective_mask, collective_op}` itself, through its DMA (`dmuser`), and the tile's only job is to carry that user unchanged — which is why the wide isolation cell and the chimney are typed with the collective types where the isle declares the layout.

**Network to isle.** Flits arriving on the router's local port become AXI again in the chimney and reach the isle's slave port through the join (joined topologies), the inbound wide adapter (isles with the collective wide layout) or the boundary adapter (macro builds). A collective is resolved in the routers; the destination isle always receives an ordinary write, which is why the inbound adapter ties the collective fields to Unicast.

**Isles with asynchronous AXI.** An isle that publishes gray-pointer FIFO buses instead of req/rsp structs - the crossbar-family isles, which carry their own half of a clock-domain crossing (`pulp_cluster_isle`) - is closed here with the counterpart cells, on the network clock: `axi_cdc_src` feeds the isle's slave side from the chimney's output, `axi_cdc_dst` takes the isle's master side towards the isolation cell or the chimney. Both are typed with the network's channel structs and sized by the isle's `LogDepth`; the isle's own half runs on the tile clock, which the control group may gate, which is what makes the crossing necessary rather than decorative. Only a single-network isle is bridged; join and dual modes raise an error, since no such isle exists and a guess would be a silent misconnection.

**Offload.** The router's reduction unit does not compute: it hands `{operand1, operand2, op}` to an offload port and waits for the result. The narrow one goes to the per-tile ALU; the wide one goes into the isle, where the cluster subtile's DCA adapter translates the FlooNoC opcode into an fpnew operation and the cluster forks the 512-bit beat into eight FP64 lanes, one per compute core's FPU.

## Two clocks, when the component has a domain of its own

A component whose `clock_domain` is not the host's makes the tile take the network clock and its power-on reset on `sys_clk_i` / `sys_rst_ni`, while `clk_i` / `rst_ni` become the domain's. The split follows the two data paths: everything the network sees - router, chimney, stamper, isolation cells, error slaves, the asynchronous bridge - runs on the network clock and resets only with the network's power-on reset; the isle, and the gating cell in front of it, run on the domain clock, and the reset it receives (`tile_rst_n_domain`) is the group or domain reset released through an `rstgen` on that clock, so its flops leave reset on the same edge. The crossing takes one of two forms. An isle with asynchronous AXI brings its own CDC half, and the tile's bridge (`axi_cdc_src` / `axi_cdc_dst`) closes it with the isle side on the domain clock and the network side on the network clock. An isle with synchronous req/rsp ports has no half of its own, so the tile instantiates a full `axi_cdc` per data path - `i_dom_cdc_<net>_mst` for the isle's masters, `i_dom_cdc_<net>_slv` for its slaves - between the `dom_<net>_in` / `dom_<net>_out` signals on the domain side and the network-side signals the type adapters, the isolation cells and the chimney already use; the crossing is typed with the network's ingress family, the collective wide type included, so the `{collective_mask, collective_op}` user travels whole (the width guard below caught the plain type truncating it to one bit). Only a component taking the wide reduction offload is refused outside the host's domain: that interface runs on the network clock and has no crossing. Every crossing half sits on the power-on reset of its own side and never on a software reset - `cdc_fifo_gray` is not warm-reset capable, and the firmware's isolation drain before a reset keeps the FIFOs empty across it.

## One discipline the template enforces

Every path above crosses at least one point where two AXI struct types meet — the isle's own types and the network's, the plain wide user and the collective one, the isolation cell's parameters and the signals on its ports. A packed struct connected or assigned across a width difference does not fail: it is shifted whole, and every field of every transaction comes out displaced, with symptoms that appear downstream and change with the width. The template therefore never copies a struct across differing types blindly: channels are rebuilt field by field where the widths may differ, the wide isolation cell is parametrized with the types its ports carry, and `$bits` guards stop elaboration with both widths in the message wherever two layouts must coincide. Four defects of exactly this class were found and fixed while the collectives were brought up; the guards are what keeps them from coming back silently.

## Reading a generated tile

Open `generated/hw/<type>_tile.sv` and look for the instance names, which are stable across projects: `i_router`, `i_alu` (narrow channel declared), `i_collective_stamper` (collective slots declared), `i_axi_narrow_out_isolate` / `i_axi_wide_out_isolate` and `i_axi_isolate_sync` (tile-owned isolation), `i_join` (joined single-port isles), `i_isle_cdc_src` / `i_isle_cdc_dst` (isles with asynchronous AXI), `i_tile_rst_sync` (components in a domain of their own), `i_chimney`, `i_isle`. The signals between them carry the network name and the direction: `narrow_in_req` is the isle's traffic *into* the network on the narrow channel, `wide_out_req` the network's traffic *out* towards the isle on the wide one, `iso_<net>_req` the isolated copy, `isle_<net>_req` the isle's own-typed side of an adaptation. The manager and memory tiles differ from a compute tile only in what their isle declares: no offload port, no collective slots, hence no ALU, no stamper and a `NoMcast` chimney. Under `ifndef SYNTHESIS` a collective-capable tile also carries the **collective trace** monitors: with `+collective_trace` the stamper prints its injections, the tile its narrow and wide reduction steps at the offload interfaces, and the landings of collective writes recognised by the contract slots on the slave side (`[COLL_TRACE]`, testbench guide section 6). They print from inside the tile and read only its own signals, because under Verilator the tile is a hierarchical block no testbench path may enter; they are silent by default and touch nothing the hardware does.
